# Anniversary / D-Day Implementation Plan

## Screen-First Scope

- Settings profile card: show couple nickname/email and days together as D+ from couple startDate.
- Couple management page: show startDate, days together, and anniversary list.
- Anniversary add/edit page: support type, title, date, icon, color, yearly repeat, notify days, shared/private.
- Calendar/home: expose upcoming anniversaries and calendar markers.

## Implementation Direction

- Use existing `Couple.startDate` as the couple start date source.
- Generate automatic anniversaries at read time instead of storing every automatic anniversary row.
- Store only user-created anniversaries and user-specific hidden states for automatic anniversaries.
- Keep FCM sending separate from this first structure pass. Notification options are stored now; scheduler/sending can be added later.

## Package Layout

- `com.hear2.anniversary.controller`
  - REST API for start date, list/detail, custom anniversary CRUD, hide/show automatic anniversaries.
- `com.hear2.anniversary.dto`
  - Request/response models for management, home, calendar, and custom create/update.
- `com.hear2.anniversary.entity`
  - User-created anniversary rows and automatic hidden-state rows.
- `com.hear2.anniversary.repository`
  - JPA repositories for stored anniversaries and hidden automatic anniversaries.
- `com.hear2.anniversary.service`
  - D+ / D-day calculation, automatic anniversary generation, sorting, validation, calendar/home integration.
- `com.hear2.anniversary.support`
  - Enums and calculation helpers.

## Initial API Plan

- `PATCH /api/v1/couples/start-date`
  - Save or update couple start date for couple status/home.
- `PUT /api/v1/anniversaries/start-date`
  - Save or update couple start date and return recalculated anniversary list.
- `GET /api/v1/anniversaries`
  - Couple management list. Includes automatic + custom anniversaries.
- `GET /api/v1/anniversaries/upcoming`
  - Home screen upcoming anniversaries.
- `POST /api/v1/anniversaries`
  - Create birthday/custom anniversary.
- `PATCH /api/v1/anniversaries/{anniversaryId}`
  - Update user-created anniversary.
- `DELETE /api/v1/anniversaries/{anniversaryId}`
  - Delete user-created anniversary.
- `POST /api/v1/anniversaries/auto/{autoGeneratedType}/hide`
  - Hide automatic anniversary.
- `DELETE /api/v1/anniversaries/auto/{autoGeneratedType}/hide`
  - Show automatic anniversary again.

## Differences From Issue Text

- Automatic anniversaries are not physically generated/saved as rows by default.
  - They are calculated from `Couple.startDate` during list/calendar/home queries.
  - Only hidden automatic anniversaries need storage.
- Alert scheduler/FCM sending is deferred.
  - `notifyDays` can be stored first.
  - Actual scheduler and duplicate-send log should be implemented after FCM policy is fixed.
- Calendar integration should add anniversary markers to calendar month responses rather than convert anniversaries into normal `CalendarEvent` rows.
